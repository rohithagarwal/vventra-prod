# vvEntra Venture Intelligence Platform
## Frontend Technology Stack

---

### 1. Summary
This document describes the technology proposed for the web frontend of the **vvEntra platform** and the plan to deliver it. The frontend is a modern, high-performance web application built with **Next.js 16**, **React 19**, and **TypeScript**. It connects seamlessly to the Python/FastAPI backend API via a versioned REST interface, providing an institutional-grade, bespoke interface for verified micro-SaaS acquisitions, revenue audits, and clean-room IP transfers.

- **Unified, Component-Driven Design**: Built with Next.js App Router and a custom editorial design system (Tailwind CSS v4 + shadcn/ui primitives), balancing rich financial data density with swift load times.
- **Type-Safe End-to-End**: Strict TypeScript paired with Zod schemas guarantees that data structures match the backend API contract at compile time and runtime.
- **Client-Side Safeguards Built-In**: Real-time form validation, input sanitization, automated token refresh lifecycle, and strict dual-role isolation (Investor vs. Architect) enforced before requests reach the network.
- **Independent & Production-Ready**: Decoupled monorepo architecture (`frontend/` and `backend/`) allowing rapid, conflict-free parallel development between frontend and backend teams.

---

### 2. Architecture Overview
- **Next.js 16 App Router**: Serves static pages instantly from the edge while orchestrating interactive client components for dynamic marketplace filters, deal workspaces, and listing composers.
- **REST API Contract**: Communicates with the FastAPI backend over HTTPS with JSON payloads. Automatically generated OpenAPI schemas from the backend serve as the strict contract between both developers.
- **Server State & Caching (TanStack Query)**: Manages remote data fetching, background polling, query deduplication, optimistic updates, and cache invalidation.
- **Client State & Forms (React Hook Form + Zod)**: Drives performant, re-render-isolated forms with real-time constraint validation and instant visual feedback.
- **Direct-to-Storage Document Uploads**: Large pitch decks, cap-table spreadsheets, and verification documents upload directly to S3-compatible storage (Cloudflare R2/AWS S3) using presigned URLs generated by the FastAPI backend—bypassing the web server.
- **Role-Gated Routing**: Client middleware and navigation guards strictly isolate Investor workflows (`/browse`, teaser requests, deal rooms) from Creator workflows (`/list`, listing manager, verification).

### 4. Why This Approach
- **Next.js & React 19**: Delivers instantaneous page loads for SEO and public discovery pages, while providing rich, desktop-class interactivity inside the authenticated member portals.
- **TanStack Query + React Hook Form + Zod**: Creates a clean separation between data fetching and UI rendering. The backend developer never has to sanitize malformed client requests, and the frontend developer never has to write manual re-fetch logic.
- **Bespoke Design System over Heavy UI Kits**: Rather than adopting a generic, bulky theme library (like AntD or MUI), building on Tailwind v4 and shadcn/ui primitives ensures vvEntra maintains its unique luxury intelligence branding (*Instrument Serif* typography, warm paper tones, refined micro-animations).
- **Playwright for Continuous Reliability**: Deal room transactions and financial disclosures require zero regressions. Automated browser testing verifies user journeys across all screen sizes before changes reach production.

---

### 5. Security and Data Protection
- **Zero Secret Leakage**: No secret credentials or sensitive tokens exist in the client-side bundle. Only public configuration variables prefixed with `NEXT_PUBLIC_` are exposed.
- **Secure Session Management**: Works in harmony with the backend’s 15-minute access token and rotating refresh token architecture via `httpOnly`, `SameSite=Lax`, and `Secure` cookies to prevent XSS-based token theft.
- **Strict Role-Based Access Control (RBAC)**: Route guards ensure Investors cannot submit or modify listings, and Architects cannot access proprietary buyer dossiers.
- **Client-Side Input Sanitization**: All user-provided rich text and listing descriptions are sanitized to prevent Cross-Site Scripting (XSS).
- **Ephemeral Sensitive Data**: Financial teasers, deal cap-tables, and verification proofs are held in memory during the active session and are never cached in unencrypted persistent storage (`localStorage`).
- **Privacy Compliance**: Cookie consent management, terms acceptance logging, and full alignment with DPDP and GDPR data handling requirements.

### 6. Risks and Mitigations

| Risk | Mitigation |
| :--- | :--- |
| **API Schema Drift Between Teams** | Backend FastAPI automatically generates OpenAPI/Swagger schemas; frontend derives TypeScript types directly to catch mismatches immediately. |
| **Large Asset Upload Latency (Pitch Decks)** | Direct client-to-S3/R2 presigned upload pipeline with chunking and visual progress bars, avoiding API bottlenecks. |
| **Complex Chart Performance on Mobile** | Use lightweight SVG paths in Recharts with debounced resize observers and container-level virtualization. |
| **Token Expiry During Long Listing Drafts** | Background silent token refresh via Axios/Fetch interceptor, combined with automated client-side draft auto-save. |
| **Cross-Browser & Device Rendering Inconsistencies** | Playwright automated matrix tests execute across Chromium, Firefox, and WebKit on mobile, tablet, and desktop viewports. |
| **Dependence on a Single Frontend Developer** | Strict TypeScript interfaces, clean modular folder structure (`components/`, `hooks/`, `lib/`), and self-documenting code ensure straightforward team handover. |
